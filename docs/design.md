# 产品与交互设计

> 核心体验目标只有两条：**位置固定** + **零阻断**。
> 版面永远不变，答完一题不做任何等待，把注意力全部留给连击。

## 1. 信息口径（"正确答案"的规则）

四个信息维度，贯穿整个产品：

| 维度 | key | 说明 |
|---|---|---|
| 全称 | `full` | 河北省 / 内蒙古自治区 / 香港特别行政区 |
| 简称 | `short` | 冀 / 内蒙古 / 沪·申（**可能多个**） |
| 省会 | `capital` | 石家庄；自治区称**首府**；直辖市与港澳**无省会** |
| 位置 | `location` | 地图上的多边形 |

必须统一的规则：

- **一省多简称**：四川=川/蜀、贵州=贵/黔、云南=云/滇、陕西=陕/秦、甘肃=甘/陇、上海=沪/申。全部可接受；选择题里它们是最好的干扰项。
- **自治区是"首府"不是"省会"**：内蒙古/广西/西藏/宁夏/新疆，题面与揭示按类型显示正确措辞。
- **直辖市与特别行政区没有省会**：凡是涉及 `capital` 的题目，这些地区直接从题源剔除。
- **易混知识点**直接进 `facts`：吉林省 ↔ 吉林市；河北省会变迁（保定/天津）。

## 2. 玩法矩阵：正交完备

一道题由三个互相独立的旋钮决定：

```
已知 known  ∈ { 全称, 简称, 省会, 位置, 随机 }
要猜 asked  ∈ { 同上，且不能与 known 相同 }
作答 style  ∈ { 填空, 三选一, 四选一, 五选一, 定位 }
```

- **12 种「已知 → 要猜」两两组合**全部可玩，包含三个**纯文字**组合（简称↔全称↔省会）。
- 每个组合都能叠加 4 种作答方式 → **48 种具体配置**。
- 「要猜 = 位置」时作答方式**强制为定位**（位置只能点地图）。
- `随机` 让已知/要猜每道题现抽。

**选择题难度**不只是选项数量，干扰项来源也不同：

| 作答方式 | 选项数 | 干扰项来源 | 得分权重 |
|---|---|---|---|
| 三选一 | 3 | 优先**跨大区**（一眼能排除） | ×0.7 |
| 四选一 | 4 | 混合 | ×0.8 |
| 五选一 | 5 | 优先**同大区**（最难） | ×0.9 |
| 填空 / 定位 | — | — | ×1.0 |

### 2.1 四种模式（只影响出题顺序与结束条件）

模式与「已知 × 要猜 × 作答方式」是正交的，随便配：

| 模式 | 出题顺序 | 什么时候结束 |
|---|---|---|
| **随机一轮**（默认） | 范围内的省份随机排一轮 | 全部答完 |
| **邻接漫游** | 从随机一个省出发，每次尽量走到**尚未访问的相邻省**；走不动（台湾/海南，或邻居被范围排除了）就跳到离当前最近的未访问省 | 全部走完 |
| **1 分钟极速** | 随机；队列用完自动重排继续 | 60 秒到 |
| **全答对为止** | 随机；**答错的题排到队尾**再来一遍 | 范围内每一省都答对过 |

实现上四种模式共用一套会话（`createSession({ order })`），区别只在队列怎么生成、以及什么时候算结束：

```js
order: "random" | "adjacency" | "endless" | "perfect"
```

- `adjacency` 用 `TERRAPOP.game.adjacencyWalk()` 生成一条覆盖全部省份的路径（实测 34 省里 26/33 步是真的接壤，其余是岛屿/飞地的跳转）。
- `endless` 在队列空时重排补充，并避免与上一题重复。
- `perfect` 在答错时把省份 push 回队尾，同时用 `solved` 记录已通关的省，`已答对 X/Y` 就是进度。

### 2.2 范围：大区 × 类型，自由组合

范围是两个独立的多选维度，任意组合（不再是一串互斥的单选）：

- **大区**：华北 / 东北 / 华东 / 华中 / 华南 / 西南 / 西北，可多选，另有「全选 / 清空」
- **类型**：省 / 自治区 / 直辖市 / 特别行政区，可多选
- 覆盖省份 = 大区 ∩ 类型。选成 0 个时开局按钮会禁用并给出提示。
- 三个快捷预设：全部 34 个、只含 23 个省、排除直辖市与港澳台。

## 3. 版面：从上到下永远三段

```
┌ 侧栏 ──────────────────────────────────────────────┐
│  ⌂   第 12 题 / 34   ⏱     🔥5 连击      得分 1240 │
│  ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░         │
├ 上一题卡片（固定位置、固定高度 232px、内部滚动）──────┤
│  答对了   贵州省            你答的是：gz            │
│  全称 贵州省 │ 简称 贵/黔 │ 省会 贵阳 │ 位置 ✓      │
│  🧠 记忆点……                                        │
│  📌 趣味知识……                                      │
│  📖 小百科（中 / 英 并排）……                        │
├────────────────────────────────────────────────────┤
│  已知 简称  冀                                      │  ← 固定
│  请说出它的「省会」                  22px 加粗      │  ← 固定、显眼
│  ┌ 作答区（固定高度 200px）──────────────────────┐  │  ← 固定
│  │ [1 贵阳 ] [2 昆明]                             │  │
│  │ [3 成都 ] [4 西安]                             │  │
│  └────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────┘
```

高度分配（900px 视口）：头部 30 + 进度 6 + 上一题卡片 232 + 当前题 312 + 间距 30 = 610，
余下的空间由当前题区块的 `margin-top: auto` 吃掉，所以**当前题永远钉在侧栏底部**——
即使上一题卡片的内容长度变化，作答区也纹丝不动。

头部的题号与进度条会跟着模式换含义：

| 模式 | 题号显示 | 进度条 |
|---|---|---|
| 随机一轮 / 邻接漫游 | `第 N 题 / 总数` | 已答 / 总数 |
| 1 分钟极速 | `第 N 题` + 右侧倒计时 | 剩余时间（随秒收缩） |
| 全答对为止 | `第 N 题 · 已答对 X / 总数` | 已答对 / 总数 |

**关键点：**

- **第一题时上方卡片是玩法说明**，之后每次都换成上一题的四维信息 + 记忆点 + 双语百科。
  卡片**压到 232px**（内部滚动），不跟下面的题目抢视觉重心。
- **答完不做任何等待**：同一帧内上方卡片换成上一题、下方同一个位置换成下一题。
  没有"揭示态"、没有自动下一题的倒计时、没有弹窗、没有需要点击的"继续"。
  连击数、得分、正确率都在头部固定显示，视线不用来回找。
- **题面 22px 加粗**，是面板里最重的字——一行就看清"要答什么"。
- 信息卡片里**简称自带带声调的拼音**（冀 · jì、川/蜀 · chuān / shǔ），
  把字形和读音绑在一起；拼音用 `lang="zh-Latn"` 标注，不会被当中文挑字体。
- **作答区高度固定 200px，位置固定**：填空题的输入框、选择题的第一个选项、定位题的提示框，
  首目标都落在同一个屏幕上坐标。选项用固定两列网格，第 1 个选项永远在左上角。
- 上方卡片高度固定、内部滚动，所以无论百科多长都不会推动下面的作答区。
- 提示（首字 / 省会标记 / 大区）占一行固定高度的位置，没有提示时留空也不跳动。
- 结算页给出**总耗时**（从开局到答完的墙钟时间）。
- **返回首页**：点左上角的品牌区（或侧栏里的 ⌂）都能回首页；如果本局还没答完，
  先弹一个确认框写明「已经答了几题 / 最高连击」，选「继续答题」会**接上原来的计时**继续，选「退出本局」才清空回首页。

## 4. 作答方式

### 位置
点击地图。命中正确省 → 对；命中**相邻省**（运行时由省界共享边算出的邻接表）或点击点距质心足够近 → 「接近」半分。
台湾、海南是岛屿没有陆上邻省，只靠质心距离兜底。设置里可切宽松 / 严格。

### 填空（智能输入）

**简称的显示只有汉字**（`津`、`川 / 蜀`）。注音属于"讲解"，单独放在信息卡片的小字里，
**不进题面、不进选项**——否则用户会把「津 (jīn)」整个抄进输入框。

同时接受**汉字、无声调拼音、拼音首字母、拉丁名、去掉行政后缀的写法**：

| 输入 | 结果 |
|---|---|
| `sjz` / `shijiazhuang` / `石家庄` | 石家庄 |
| `sj` / `f`（唯一命中**且就是正确答案**） | **自动判定，不用回车** |
| `hn` | 河南 / 湖南 / 海南 → **列候选**，↑↓ 选、回车确定 |
| 唯一命中但**答的是别的省** | **不提交**，等你按回车——方便改错 |
| `津 (jīn)`（原样抄界面显示） | 天津 ✓ |
| `川 / 蜀` / `贵/黔` | 四川 / 贵州 ✓（多简称整串写也算） |
| `石家` | 石家庄（前缀在提交时也算对） |
| `廣東省` | 广东（繁简折叠 + 去后缀） |
| `Hebei Province` | 河北（英文名、多词首字母 `hp`） |
| `羊城` / `石头城` | 广州 / 南京（**别称只认完整输入**，不参与前缀匹配） |

**三条输入规则**（都是为了别打断手感、别误判）：

1. **只有"唯一命中且命中的就是正确答案"才自动判定。** 唯一但答的是别的省份时**不会**自动提交。
2. **出现多个候选时用 `↑↓` 选、回车提交**，界面上直接写着这行提示；`Esc` 取消高亮。
3. **界面上显示什么，就一定能原样判对。** 输入会被展开成几种等价形态：
   只留汉字、归一化原文、只留拉丁——所以「津 (jīn)」「川 / 蜀 (chuān / shǔ)」都能判对；
   多简称还可以用 `/`、`、`、`,`、`;` 分隔后逐段判定。
   匹配时**汉字形态优先**，这样「津 (jīn)」先按汉字命中天津，
   不会因为 `jin` 同时是「晋」的拼音而误判成多候选。

实现上每个维度分 **primary**（正式名称 / 简称 / 省会 / 拼音 / 首字母）与 **extra**（别称）两层，
**前缀匹配只看 primary**，判定规则与匹配规则一致。

### 选择（三 / 四 / 五选一）
固定两列网格，选项带 `1-5` 数字快捷键，点选或按数字键即提交。

## 6. 视觉：低调的地图 + 一眼可见的高亮

**两条相互让步的原则**：地图尽量安静，高亮必须刺眼。

- **地图低调**：省份填色只用极低饱和的暖灰调（非目标省的颜色通道差中位数约 5、最大 30），
  省界是细浅线 + 白描边，地貌压到 0.34–0.42 不透明度。整幅图接近单色纸感。
- **高亮刺眼**：已知位置时对**整幅地图压一层白色薄纱**（74% 不透明），
  只把目标省从遮罩里"挖空"，再叠上饱和金色填充 + 深金描边 + 白色光环脉动。
  目标省的通道差会从 ~5 跳到 ~107，屏幕上只有一个亮点。
- **地貌标注不许泄露省份**：面状地貌一律只标**类型名**（高原 / 盆地 / 平原 / 沙漠 / 丘陵），
  绝不写「四川盆地」这种。山脉 / 河流 / 湖泊保留名字，但名字里含省名或简称的**直接不标**——
  例如黑龙江（江与省同名）、雅鲁藏布江（藏）、青海湖（青）、滇池（滇）、秦岭（秦）。
  这套规则由 `T.map.buildForbiddenWords()` + `leaks()` 统一实现，自检脚本会验证。

**地貌图层**（画在省份填色之上、半透明，既能看到大区配色又能看到地形）：

- 高原（青藏 / 内蒙古 / 黄土 / 云贵）：暖米色 + 等高线斜纹
- 盆地（塔里木 / 准噶尔 / 柴达木 / 四川）、平原（东北 / 华北 / 长江中下游）、丘陵（东南丘陵）：淡绿系
- 沙漠（塔克拉玛干）：沙点纹理
- 山脉 16 条（天山 / 昆仑 / 喜马拉雅 / 秦岭 / 大兴安岭 / 太行 / 横断 / 南岭 / 武夷…）：沿真实走向排列的山形符号
- 河流 9 条（长江 / 黄河 / 珠江 / 黑龙江 / 松花江 / 淮河 / 澜沧江 / 雅鲁藏布江 / 塔里木河）：白描边 + 淡蓝线芯
- 湖泊 13 个（青海湖 / 鄱阳 / 洞庭 / 太湖 / 洪泽 / 巢湖 / 呼伦湖 / 滇池 / 洱海 / 纳木错 / 博斯腾 / 兴凯 / 长白山天池）
- 左上角有**图例**，可关

所有面状地貌都用 `clipPath` 裁在陆地轮廓内，手绘椭圆画大了一圈也不会溢到海里。
南海诸岛与九段线用右下角**插图框**，港澳用**放大框**解决点击目标过小。
**港澳高亮时放大框里会同步高亮**（否则主图上那几个像素根本看不出被圈了），
放大框内的描边用 `vector-effect: non-scaling-stroke`，放大 9 倍也不会变成粗块。

## 7. 字体（踩过坑，写下来免得再犯）

字体栈只有一个来源：`css/style.css` 里的 `--round`。排布必须满足三条：

1. **拉丁字母 / 数字 / 拼音声调字符，要由"排在中文之前、且覆盖 Latin Extended-B"的字体提供。**
   拼音的 `ǒ ǔ ǎ ě ǖǘǚǜ` 属于 Latin Extended-B，**苹方（PingFang SC）并不覆盖它们**。
   如果让苹方先命中，同一个音节里就会出现"`sh` 用一个字体、`ǔ` 用另一个字体"的混排。
   所以 `Helvetica Neue` / `Segoe UI` / `Helvetica` / `Arial` 排在中文之前。
2. **中文只交给中文字体，绝不放日文字体。**
   早期版本把 `"Hiragino Maru Gothic ProN"`（日文圆体）排在 `"PingFang SC"` 前面，
   结果拉丁字有字形、汉字缺字，浏览器就一路落到日文字体，**汉字按日文字形渲染**——
   这就是"字体看起来怪怪的"的根因。现在栈里没有任何日文字体。
3. **汉字内容显式标 `lang="zh-Hans"`。** 界面切成英文时 `<html lang>` 会变成 `en`，
   这时汉字得靠自己声明语言，浏览器才会挑中文字体。
   `js/app.js` 的 `markLang()` 与 `js/map.js` 的地貌标注都会按需加这个属性。

另外：`ui-rounded` / `"SF Pro Rounded"` 在 Chromium 里**不解析**（实测会落到 Helvetica），
留着只是为了在 Safari 上拿到圆体，不影响其它浏览器的结果。

这三条在端到端里都有回归断言：用 CDP 的 `CSS.getPlatformFontsForNode` 读**实际用到的字体**，
要求汉字只用一种字体且不是日文字体、拼音声调字符只用一种字体（见 `tests/e2e.mjs`）。

## 8. 音效与语音

- **音效**（WebAudio 现场合成，零素材）：答对三音琶音、音高**随连击递升**；接近两个中性音；答错下行锯齿音；结算四音符。
- **语音**：`speak()` 已实现朗读题面与答案；`listen()` 是 stub，作答入口已统一成 `commit({kind, value|regionId})`。

## 9. 移动端与可访问性

- 窄屏下地图与侧栏纵向堆叠，上方卡片改为限高滚动。
- 地图支持双指缩放与拖拽；选项带 `1-5` 快捷键；回车提交；Esc 关设置。
- 对错不只靠红绿：同时用 ✓ / ≈ / ✗ 与边框样式表达。
- 尊重 `prefers-reduced-motion`，并提供「动画」开关。
